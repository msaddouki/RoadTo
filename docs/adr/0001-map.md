# ADR 0001 — Map: MapLibre and PMTiles

- Status: accepted (POC), to confirm with spike A
- Date: 2026-10-16

## Context

The map must show without network on the test region (milestone J2), on
Android and iOS from one Flutter app (ADR 0004), on phones without Google
services, and without an account, an API key or a tracker. Driving puts the
map on screen for an hour at a time, day and night.

## Decision

- **MapLibre Native** draws the map, through the `maplibre_gl` Flutter
  plugin (0.27; MapLibre Android 13.5 in its OpenGL variant, MapLibre iOS
  6.28). Vector tiles, rendered on the GPU, with the same style format on
  both platforms.
- **Offline tiles are one PMTiles file** per region (`map.pmtiles`,
  OpenMapTiles schema, built by Planetiler), read in place by MapLibre
  (`pmtiles://file://…`): no tile server on the phone, no unpacking, no
  SQLite. Its packaging, signature and updates are in ADR 0009.
- **Style**: OpenFreeMap Liberty, rewritten by the region pipeline to point
  at the local file, with its sprites and fonts in the package (Latin, Greek
  and Cyrillic glyph ranges only). The pipeline also derives a **night
  style** from it (`roadto_pipeline night`): same layers, colours inverted
  and dimmed, roads kept the lightest. The app switches to it from sunset to
  sunrise where the car is, computed offline.
- **Online fallback**: outside an installed region, or with the offline map
  turned off, the app shows OpenFreeMap's hosted styles (free, no key, no
  tracking).
- **The app draws its own layers** as GeoJSON sources (route, alerts,
  destination, position) above the style. MapLibre's location component is
  never enabled: in the Flutter plugin it starts a Google Play Services
  location engine, and the Android build excludes those libraries. The
  position comes from `DeviceLocation` (Android's LocationManager) or
  CoreLocation.

## Alternatives

- **Google Maps or Mapbox SDKs**: API keys, usage tracking, terms that
  forbid or price offline use, and Google Play Services on Android.
- **flutter_map** (map drawn in Dart): its vector tile support is young and
  slower than a native GPU renderer on a long drive; raster tiles would
  make offline regions far larger.
- **MBTiles**: a SQLite file needing a local tile server or a custom
  source; PMTiles is read directly by MapLibre on both platforms.

## Consequences

- Style changes are pipeline work (Python) and reach phones with the next
  region package, not with an app release.
- The Flutter plugin lags behind MapLibre Native; it is pinned and its
  Android build is checked for Google libraries in CI.
- Android Auto and CarPlay (J4, J8) cannot reuse the Flutter widget: the
  car screen needs MapLibre drawn natively on the car surface (spike D).
- Still to measure on devices (spike A): frame rate while following the
  car, memory, battery over an hour, and labels on the PMTiles map on both
  platforms.
